# Machine-token kinds

`beam.accounts.tokens.kinds` holds the **machine-token kinds**: `name => class-string` of a
`SamePrincipalTokenKind` or a `DelegatedTokenKind`. `Tokens\MachineTokenIssuer` mints only a kind declared
here, records the name in the token's `kind` column, and refuses `*` whatever the kind returns (fleet ADR 0006,
rule 3). A login token is not a kind: `Auth\AuthTokenFactory` mints it, and it is the only `*` token.

## Declaring a kind

The package declares `personal-access-token`. A package or host that mints a token for **another** principal
declares a delegated kind under its own name:

```php
'tokens' => [
    'kinds' => [
        'personal-access-token' => \Splicewire\Beam\Accounts\Tokens\Kinds\PersonalAccessTokenKind::class,
        'satellite-tenant' => \App\Tokens\SatelliteTenantKind::class,
    ],
],
```

A **same-principal** kind (`SamePrincipalTokenKind::abilities($principal, $requested)`) mints for the actor.
Under a scoped acting token its set may hold nothing that token lacks (`token_abilities_beyond_acting_token`).

A **delegated** kind (`DelegatedTokenKind`) mints for a principal the kind resolves, never one the caller names:

| method | what it declares |
|---|---|
| `issuanceAbility()` | the ability a scoped acting credential must carry (`token_issuance_ability_missing`) |
| `boundSubject($actor)` | the subject it binds to from its own context, such as the current tenant (required). A request naming another subject, or naming one when this is null, is `token_target_mismatch`; the request's subject is never used instead |
| `resolveTarget($actor, $subject)` | the token's principal; null is `token_target_unresolved`, a request naming another is `token_target_mismatch`, and the actor itself is `token_target_is_actor` |
| `authorizes($actor, $target, $subject)` | the actor's live authority over the target (`token_target_no_authority`) |
| `abilities($target, $subject)` | the declared set, exactly what the consumer calls; a request naming abilities is `token_kind_declares_abilities` |

An **operation** kind (`OperationTokenKind`, a delegated kind) binds to the object the calling code is operating
on rather than to the actor's ambient context: a federation grant, a brokered child tenant, the tenant an operator
makes a broker. The code that performs the operation passes it, never a request body:
`$issuer->issueFor('satellite-tenant', $child, new TokenIssuance(actor: …, name: …))`. It is the kind's only
subject (`boundSubject()` is final); `issue()` on such a kind resolves none and is refused, `issueFor()` on any
other kind is `token_kind_not_operation_bound`, and `authorizes()` must still establish the actor's live authority
over the target for that operation.

A **deterministic** key (a reset-surviving `{id}|{plaintext}` bearer two hosts mint independently) is a request
with `deterministicId` and `deterministicPlaintext`; the row is upserted under the fixed id. From a console,
`splicewire:beam:accounts:mint-key {kind} {id} {plaintext}` (gated on `beam.accounts.keys.enabled`) issues one for
a declared kind that admits a console issuance.

Nothing is issued while `beam.accounts.api.scope_enforcement` is off (`token_issuer_enforcement_off`).

## Who reads it

`Tokens\MachineTokenIssuer`, through `Tokens\TokenKindRegistry::kind($name)`. An undeclared name, or a class that
is neither shape, is `token_kind_undeclared`.

## The widest set

`Tokens\WidestTokenScope::for($user)` is what an empty or `*` personal-token request becomes, and what the Tokens
page picker offers: the user's permission-name snapshot plus the names each `Contracts\DecisionNameSource` reports.
`Tokens\CascadeDecisionNameSource` is built in (read even where a host's published `tokens` config has no
`decision_name_sources` key): every name registered in the cascade's `DecisionNames` and each policy verb's
class-level names (`CredentialScopeGate::offerableNames()`), never a per-record name. A host adds its own sources in
`beam.accounts.tokens.decision_name_sources`. Offering a name grants nothing: the principal half still decides.

## No other writer

`splicewire:beam:accounts:token-writes [paths…] [--exclude=path…]` lists every token write outside
`AuthTokenFactory` and the issuer (`createToken`, a token-model write, a query-builder write to the token table, a
direct use of the retired `DeterministicToken`) and exits 1 when there is one. Every excluded path is printed
(`excluded: …`), so a fleet run that leaves a repository out says so.
